ECS Deployment Pipeline

Push-to-deploy to Amazon ECS from gh-pages via GitHub Actions and OIDC. Everything you need — workflow, IAM, bootstrap script, docs, and release notes — in one page.

Auth

GitHub OIDC — no long-lived AWS keys stored in GitHub.

Compute

ECS on Fargate, single container, awslogs driver.

Registry

Amazon ECR, image tagged with commit SHA.

Trigger

Push to gh-pages.

Overview

Setiap push ke cawangan gh-pages akan:

  1. Mengambil kredential AWS sementara melalui GitHub OIDC.
  2. Membina imej Docker dan menolaknya ke Amazon ECR dengan tag ${{ github.sha }}.
  3. Meletakkan imej baharu ke dalam task definition ECS.
  4. Mendaftar task definition dan mengemas kini ECS service.
  5. Menunggu service stabil sebelum tamat.

Flow diagram

push to gh-pages → assume AWS role (OIDC) → docker build → push to ECR (SHA tag) → render task def → register + update service → wait for stability

Prerequisites

  • AWS CLI v2, authenticated dengan kredential yang boleh mencipta IAM roles, ECR repos, ECS clusters/services, dan OIDC providers.
  • VPC sedia ada dengan:
    • Dua atau lebih subnet yang mempunyai route ke NAT gateway atau internet gateway.
    • Security group yang membenarkan inbound pada port kontena (atau ALB di hadapan).
  • Repositori GitHub dengan Actions diaktifkan.

Skrip ini akan mencipta atau mengesahkan:

  • ECS cluster dan service

Workflow — .github/workflows/aws.yml

Gunakan versi OIDC ini. Ia tidak menyimpan access key dalam GitHub secrets.

.github/workflows/aws.yml 
name: Deploy to Amazon ECS

on:
  push:
    branches: [ "gh-pages" ]

env:
  AWS_REGION: us-east-2
  ECR_REPOSITORY: my-ecr-repo
  ECS_SERVICE: my-ecs-service
  ECS_CLUSTER: my-ecs-cluster
  ECS_TASK_DEFINITION: .aws/task-definition.json
  CONTAINER_NAME: my-container

permissions:
  id-token: write
  contents: read

jobs:
  deploy:
    name: Deploy
    runs-on: ubuntu-latest
    environment: production

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Configure AWS credentials (OIDC)
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::YOUR_ACCOUNT_ID:role/github-actions-ecs-deploy-oidc
          aws-region: ${{ env.AWS_REGION }}

      - name: Login to Amazon ECR
        id: login-ecr
        uses: aws-actions/amazon-ecr-login@v2

      - name: Build, tag, and push image to Amazon ECR
        id: build-image
        env:
          ECR_REGISTRY: ${{ steps.login-ecr.outputs.registry }}
          IMAGE_TAG: ${{ github.sha }}
        run: |
          docker build -t $ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG .
          docker push $ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG
          echo "image=$ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG" >> $GITHUB_OUTPUT

      - name: Fill in the new image ID in the Amazon ECS task definition
        id: task-def
        uses: aws-actions/amazon-ecs-render-task-definition@v1
        with:
          task-definition: ${{ env.ECS_TASK_DEFINITION }}
          container-name: ${{ env.CONTAINER_NAME }}
          image: ${{ steps.build-image.outputs.image }}

      - name: Deploy Amazon ECS task definition
        uses: aws-actions/amazon-ecs-deploy-task-definition@v2
        with:
          task-definition: ${{ steps.task-def.outputs.task-definition }}
          service: ${{ env.ECS_SERVICE }}
          cluster: ${{ env.ECS_CLUSTER }}
          wait-for-service-stability: true
Fallback access-key auth. Jika perlu, gantikan step OIDC dengan: 
- name: Configure AWS credentials
  uses: aws-actions/configure-aws-credentials@v4
  with:
    aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
    aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
    aws-region: ${{ env.AWS_REGION }}
OIDC tetap lebih disyorkan.

Bootstrap — deploy.sh

Skrip idempotent. Selamat dijalankan berulang kali.

deploy.sh 
#!/usr/bin/env bash
#
# deploy.sh — one-shot setup for the GitHub Actions → Amazon ECS pipeline.
#
set -euo pipefail

# ---------------------------------------------------------------------------
# CONFIG — edit these
# ---------------------------------------------------------------------------
AWS_REGION="us-east-2"
AWS_ACCOUNT_ID="$(aws sts get-caller-identity --query Account --output text)"

ECR_REPO="my-ecr-repo"
ECS_CLUSTER="my-ecs-cluster"
ECS_SERVICE="my-ecs-service"
ECS_TASK_FAMILY="my-task"
CONTAINER_NAME="my-container"
CONTAINER_PORT="80"

GITHUB_ORG="OWNER"
GITHUB_REPO="REPO"
GITHUB_BRANCH="gh-pages"

VPC_SUBNETS="subnet-xxxxxxxx,subnet-yyyyyyyy"
VPC_SECURITY_GROUPS="sg-xxxxxxxx"

OIDC_ROLE_NAME="github-actions-ecs-deploy-oidc"
EXEC_ROLE_NAME="ecsTaskExecutionRole"

TASK_DEF_FILE=".aws/task-definition.json"
# ---------------------------------------------------------------------------

log()  { printf "\n\033[1;34m==>\033[0m %s\n" "$*"; }

# 0. Sanity checks
log "Verifying AWS identity"
aws sts get-caller-identity >/dev/null
echo "Account: $AWS_ACCOUNT_ID  Region: $AWS_REGION"

# 1. ECR repository
log "Ensuring ECR repository: $ECR_REPO"
if aws ecr describe-repositories --repository-names "$ECR_REPO" \
     --region "$AWS_REGION" >/dev/null 2>&1; then
  echo "already exists"
else
  aws ecr create-repository \
    --repository-name "$ECR_REPO" \
    --image-scanning-configuration scanOnPush=true \
    --region "$AWS_REGION" >/dev/null
  echo "created"
fi

ECR_URI="${AWS_ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com/${ECR_REPO}"

# 2. ECS cluster
log "Ensuring ECS cluster: $ECS_CLUSTER"
if aws ecs describe-clusters --clusters "$ECS_CLUSTER" \
     --region "$AWS_REGION" \
     --query 'clusters[?status==`ACTIVE`]' --output text | grep -q "$ECS_CLUSTER"; then
  echo "already exists"
else
  aws ecs create-cluster --cluster-name "$ECS_CLUSTER" \
    --region "$AWS_REGION" >/dev/null
  echo "created"
fi

# 3. ECS task execution role
log "Ensuring IAM role: $EXEC_ROLE_NAME"
if aws iam get-role --role-name "$EXEC_ROLE_NAME" >/dev/null 2>&1; then
  echo "already exists"
else
  aws iam create-role \
    --role-name "$EXEC_ROLE_NAME" \
    --assume-role-policy-document '{
      "Version":"2012-10-17",
      "Statement":[{
        "Effect":"Allow",
        "Principal":{"Service":"ecs-tasks.amazonaws.com"},
        "Action":"sts:AssumeRole"
      }]
    }' >/dev/null
  aws iam attach-role-policy \
    --role-name "$EXEC_ROLE_NAME" \
    --policy-arn arn:aws:iam::aws:policy/service-role/AmazonECSTaskExecutionRolePolicy
  echo "created"
fi
EXEC_ROLE_ARN="arn:aws:iam::${AWS_ACCOUNT_ID}:role/${EXEC_ROLE_NAME}"

# 4. Task definition file
log "Writing task definition: $TASK_DEF_FILE"
mkdir -p "$(dirname "$TASK_DEF_FILE")"
cat > "$TASK_DEF_FILE" <<JSON
{
  "family": "${ECS_TASK_FAMILY}",
  "networkMode": "awsvpc",
  "requiresCompatibilities": ["FARGATE"],
  "cpu": "256",
  "memory": "512",
  "executionRoleArn": "${EXEC_ROLE_ARN}",
  "containerDefinitions": [
    {
      "name": "${CONTAINER_NAME}",
      "image": "PLACEHOLDER",
      "essential": true,
      "portMappings": [
        { "containerPort": ${CONTAINER_PORT}, "protocol": "tcp" }
      ],
      "logConfiguration": {
        "logDriver": "awslogs",
        "options": {
          "awslogs-group": "/ecs/${ECS_TASK_FAMILY}",
          "awslogs-region": "${AWS_REGION}",
          "awslogs-stream-prefix": "ecs",
          "awslogs-create-group": "true"
        }
      }
    }
  ]
}
JSON
echo "written"

log "Registering task definition"
aws ecs register-task-definition \
  --cli-input-json "file://${TASK_DEF_FILE}" \
  --region "$AWS_REGION" >/dev/null
echo "registered family: $ECS_TASK_FAMILY"

# 5. ECS service
log "Ensuring ECS service: $ECS_SERVICE"
if aws ecs describe-services \
     --cluster "$ECS_CLUSTER" --services "$ECS_SERVICE" \
     --region "$AWS_REGION" \
     --query 'services[?status==`ACTIVE`]' --output text | grep -q "$ECS_SERVICE"; then
  echo "already exists"
else
  aws ecs create-service \
    --cluster "$ECS_CLUSTER" \
    --service-name "$ECS_SERVICE" \
    --task-definition "$ECS_TASK_FAMILY" \
    --desired-count 1 \
    --launch-type FARGATE \
    --network-configuration "awsvpcConfiguration={subnets=[${VPC_SUBNETS}],securityGroups=[${VPC_SECURITY_GROUPS}],assignPublicIp=ENABLED}" \
    --region "$AWS_REGION" >/dev/null
  echo "created"
fi

# 6. GitHub OIDC provider
log "Ensuring GitHub OIDC provider"
OIDC_ARN="arn:aws:iam::${AWS_ACCOUNT_ID}:oidc-provider/token.actions.githubusercontent.com"
if aws iam list-open-id-connect-providers \
     --query "OpenIDConnectProviderList[?Arn=='${OIDC_ARN}'].Arn" \
     --output text | grep -q .; then
  echo "already exists"
else
  aws iam create-open-id-connect-provider \
    --url https://token.actions.githubusercontent.com \
    --client-id-list sts.amazonaws.com \
    --thumbprint-list 6938fd4d98bab03faadb97b34396831e3780aea1 >/dev/null
  echo "created"
fi

# 7. GitHub Actions deploy role (OIDC trust)
log "Ensuring deploy role: $OIDC_ROLE_NAME"
TRUST_FILE="$(mktemp)"
cat > "$TRUST_FILE" <<JSON
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "${OIDC_ARN}"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "token.actions.githubusercontent.com:aud": "sts.amazonaws.com"
        },
        "StringLike": {
          "token.actions.githubusercontent.com:sub": "repo:${GITHUB_ORG}/${GITHUB_REPO}:ref:refs/heads/${GITHUB_BRANCH}"
        }
      }
    }
  ]
}
JSON

if aws iam get-role --role-name "$OIDC_ROLE_NAME" >/dev/null 2>&1; then
  echo "already exists — updating trust policy"
  aws iam update-assume-role-policy \
    --role-name "$OIDC_ROLE_NAME" \
    --policy-document "file://${TRUST_FILE}"
else
  aws iam create-role \
    --role-name "$OIDC_ROLE_NAME" \
    --assume-role-policy-document "file://${TRUST_FILE}" >/dev/null
  echo "created"
fi
rm -f "$TRUST_FILE"

DEPLOY_POLICY_FILE="$(mktemp)"
cat > "$DEPLOY_POLICY_FILE" <<JSON
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ECRAuth",
      "Effect": "Allow",
      "Action": "ecr:GetAuthorizationToken",
      "Resource": "*"
    },
    {
      "Sid": "ECRPushPull",
      "Effect": "Allow",
      "Action": [
        "ecr:BatchCheckLayerAvailability",
        "ecr:GetDownloadUrlForLayer",
        "ecr:BatchGetImage",
        "ecr:InitiateLayerUpload",
        "ecr:UploadLayerPart",
        "ecr:CompleteLayerUpload",
        "ecr:PutImage"
      ],
      "Resource": "arn:aws:ecr:${AWS_REGION}:${AWS_ACCOUNT_ID}:repository/${ECR_REPO}"
    },
    {
      "Sid": "ECSRegisterAndDeploy",
      "Effect": "Allow",
      "Action": [
        "ecs:RegisterTaskDefinition",
        "ecs:DescribeTaskDefinition",
        "ecs:UpdateService",
        "ecs:DescribeServices"
      ],
      "Resource": "*"
    },
    {
      "Sid": "PassRoleToECS",
      "Effect": "Allow",
      "Action": "iam:PassRole",
      "Resource": [
        "arn:aws:iam::${AWS_ACCOUNT_ID}:role/${EXEC_ROLE_NAME}",
        "arn:aws:iam::${AWS_ACCOUNT_ID}:role/ecsTaskRole"
      ]
    }
  ]
}
JSON

aws iam put-role-policy \
  --role-name "$OIDC_ROLE_NAME" \
  --policy-name GitHubActionsECSDeploy \
  --policy-document "file://${DEPLOY_POLICY_FILE}"
rm -f "$DEPLOY_POLICY_FILE"

DEPLOY_ROLE_ARN="arn:aws:iam::${AWS_ACCOUNT_ID}:role/${OIDC_ROLE_NAME}"

# 8. Summary

Branching model

Review checklist

  • Tests pass locally.
  • docker build succeeds.
  • Perubahan pada workflow / task def / deploy.sh diuji pada non-prod AWS.
  • Tiada secrets, ARN, atau account ID di-commit.
  • README / docs dikemas kini jika behaviour berubah.

Rules

  • Jangan push terus ke gh-pages tanpa review kecuali hotfix.
  • Jangan commit AWS credentials. Guna OIDC.
  • Jika ubah OIDC trust policy, koordinasi dengan pemilik akaun AWS.
  • Rollback = re-run workflow lama, bukan git revert + push.

PR description

Add ECS deployment workflow with setup instructions

Summary

Adds a GitHub Actions workflow that builds a Docker image, pushes it to Amazon ECR, and rolls out a new task definition to Amazon ECS on every push to gh-pages. Includes an idempotent AWS setup script and a task definition template.

Setup checklist (before merging)

  • Run ./deploy.sh.
  • Paste printed env: block into aws.yml.
  • Paste printed role-to-assume ARN.
  • Confirm permissions: id-token: write.
  • Verify subnets have NAT/IGW route.
  • Verify SG allows inbound on container port.

ECS Deployment Pipeline

Push-to-deploy to Amazon ECS from gh-pages via GitHub Actions and OIDC. Everything you need — workflow, IAM, bootstrap script, docs, and release notes — in one page.

Auth

GitHub OIDC — no long-lived AWS keys stored in GitHub.

Compute

ECS on Fargate, single container, awslogs driver.

Registry

Amazon ECR, image tagged with commit SHA.

Trigger

Push to gh-pages.

Overview

Setiap push ke cawangan gh-pages akan:

  1. Mengambil kredential AWS sementara melalui GitHub OIDC.
  2. Membina imej Docker dan menolaknya ke Amazon ECR dengan tag ${{ github.sha }}.
  3. Meletakkan imej baharu ke dalam task definition ECS.
  4. Mendaftar task definition dan mengemas kini ECS service.
  5. Menunggu service stabil sebelum tamat.

Flow diagram

push to gh-pages → assume AWS role (OIDC) → docker build → push to ECR (SHA tag) → render task def → register + update service → wait for stability

Prerequisites

  • AWS CLI v2, authenticated dengan kredential yang boleh mencipta IAM roles, ECR repos, ECS clusters/services, dan OIDC providers.
  • VPC sedia ada dengan:
    • Dua atau lebih subnet yang mempunyai route ke NAT gateway atau internet gateway.
    • Security group yang membenarkan inbound pada port kontena (atau ALB di hadapan).
  • Repositori GitHub dengan Actions diaktifkan.

Workflow — .github/workflows/aws.yml

Gunakan versi OIDC ini. Ia tidak menyimpan access key dalam GitHub secrets.

.github/workflows/aws.yml 
name: Deploy to Amazon ECS

on:
  push:
    branches: [ "gh-pages" ]

env:
  AWS_REGION: us-east-2
  ECR_REPOSITORY: my-ecr-repo
  ECS_SERVICE: my-ecs-service
  ECS_CLUSTER: my-ecs-cluster
  ECS_TASK_DEFINITION: .aws/task-definition.json
  CONTAINER_NAME: my-container

permissions:
  id-token: write
  contents: read

jobs:
  deploy:
    name: Deploy
    runs-on: ubuntu-latest
    environment: production

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Configure AWS credentials (OIDC)
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::YOUR_ACCOUNT_ID:role/github-actions-ecs-deploy-oidc
          aws-region: ${{ env.AWS_REGION }}

      - name: Login to Amazon ECR
        id: login-ecr
        uses: aws-actions/amazon-ecr-login@v2

      - name: Build, tag, and push image to Amazon ECR
        id: build-image
        env:
          ECR_REGISTRY: ${{ steps.login-ecr.outputs.registry }}
          IMAGE_TAG: ${{ github.sha }}
        run: |
          docker build -t $ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG .
          docker push $ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG
          echo "image=$ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG" >> $GITHUB_OUTPUT

      - name: Fill in the new image ID in the Amazon ECS task definition
        id: task-def
        uses: aws-actions/amazon-ecs-render-task-definition@v1
        with:
          task-definition: ${{ env.ECS_TASK_DEFINITION }}
          container-name: ${{ env.CONTAINER_NAME }}
          image: ${{ steps.build-image.outputs.image }}

      - name: Deploy Amazon ECS task definition
        uses: aws-actions/amazon-ecs-deploy-task-definition@v2
        with:
          task-definition: ${{ steps.task-def.outputs.task-definition }}
          service: ${{ env.ECS_SERVICE }}
          cluster: ${{ env.ECS_CLUSTER }}
          wait-for-service-stability: true
Fallback access-key auth. Jika perlu, gantikan step OIDC dengan: 
- name: Configure AWS credentials
  uses: aws-actions/configure-aws-credentials@v4
  with:
    aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
    aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
    aws-region: ${{ env.AWS_REGION }}

Bootstrap — deploy.sh

Skrip idempotent. Selamat dijalankan berulang kali.

deploy.sh 
#!/usr/bin/env bash
#
# deploy.sh — one-shot setup for the GitHub Actions → Amazon ECS pipeline.
#
set -euo pipefail

# ---------------------------------------------------------------------------
# CONFIG — edit these
# ---------------------------------------------------------------------------
AWS_REGION="us-east-2"
AWS_ACCOUNT_ID="$(aws sts get-caller-identity --query Account --output text)"

ECR_REPO="my-ecr-repo"
ECS_CLUSTER="my-ecs-cluster"
ECS_SERVICE="my-ecs-service"
ECS_TASK_FAMILY="my-task"
CONTAINER_NAME="my-container"
CONTAINER_PORT="80"

GITHUB_ORG="OWNER"
GITHUB_REPO="REPO"
GITHUB_BRANCH="gh-pages"

VPC_SUBNETS="subnet-xxxxxxxx,subnet-yyyyyyyy"
VPC_SECURITY_GROUPS="sg-xxxxxxxx"

OIDC_ROLE_NAME="github-actions-ecs-deploy-oidc"
EXEC_ROLE_NAME="ecsTaskExecutionRole"

TASK_DEF_FILE=".aws/task-definition.json"
# ---------------------------------------------------------------------------

log()  { printf "\n\033[1;34m==>\033[0m %s\n" "$*"; }

# 0. Sanity checks
log "Verifying AWS identity"
aws sts get-caller-identity >/dev/null
echo "Account: $AWS_ACCOUNT_ID  Region: $AWS_REGION"

# 1. ECR repository
log "Ensuring ECR repository: $ECR_REPO"
if aws ecr describe-repositories --repository-names "$ECR_REPO" \
     --region "$AWS_REGION" >/dev/null 2>&1; then
  echo "already exists"
else
  aws ecr create-repository \
    --repository-name "$ECR_REPO" \
    --image-scanning-configuration scanOnPush=true \
    --region "$AWS_REGION" >/dev/null
  echo "created"
fi

ECR_URI="${AWS_ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com/${ECR_REPO}"

# 2. ECS cluster
log "Ensuring ECS cluster: $ECS_CLUSTER"
if aws ecs describe-clusters --clusters "$ECS_CLUSTER" \
     --region "$AWS_REGION" \
     --query 'clusters[?status==`ACTIVE`]' --output text | grep -q "$ECS_CLUSTER"; then
  echo "already exists"
else
  aws ecs create-cluster --cluster-name "$ECS_CLUSTER" \
    --region "$AWS_REGION" >/dev/null
  echo "created"
fi

# 3. ECS task execution role
log "Ensuring IAM role: $EXEC_ROLE_NAME"
if aws iam get-role --role-name "$EXEC_ROLE_NAME" >/dev/null 2>&1; then
  echo "already exists"
else
  aws iam create-role \
    --role-name "$EXEC_ROLE_NAME" \
    --assume-role-policy-document '{
      "Version":"2012-10-17",
      "Statement":[{
        "Effect":"Allow",
        "Principal":{"Service":"ecs-tasks.amazonaws.com"},
        "Action":"sts:AssumeRole"
      }]
    }' >/dev/null
  aws iam attach-role-policy \
    --role-name "$EXEC_ROLE_NAME" \
    --policy-arn arn:aws:iam::aws:policy/service-role/AmazonECSTaskExecutionRolePolicy
  echo "created"
fi
EXEC_ROLE_ARN="arn:aws:iam::${AWS_ACCOUNT_ID}:role/${EXEC_ROLE_NAME}"

# 4. Task definition file
log "Writing task definition: $TASK_DEF_FILE"
mkdir -p "$(dirname "$TASK_DEF_FILE")"
cat > "$TASK_DEF_FILE" <<JSON
{
  "family": "${ECS_TASK_FAMILY}",
  "networkMode": "awsvpc",
  "requiresCompatibilities": ["FARGATE"],
  "cpu": "256",
  "memory": "512",
  "executionRoleArn": "${EXEC_ROLE_ARN}",
  "containerDefinitions": [
    {
      "name": "${CONTAINER_NAME}",
      "image": "PLACEHOLDER",
      "essential": true,
      "portMappings": [
        { "containerPort": ${CONTAINER_PORT}, "protocol": "tcp" }
      ],
      "logConfiguration": {
        "logDriver": "awslogs",
        "options": {
          "awslogs-group": "/ecs/${ECS_TASK_FAMILY}",
          "awslogs-region": "${AWS_REGION}",
          "awslogs-stream-prefix": "ecs",
          "awslogs-create-group": "true"
        }
      }
    }
  ]
}
JSON
echo "written"

log "Registering task definition"
aws ecs register-task-definition \
  --cli-input-json "file://${TASK_DEF_FILE}" \
  --region "$AWS_REGION" >/dev/null
echo "registered family: $ECS_TASK_FAMILY"

# 5. ECS service
log "Ensuring ECS service: $ECS_SERVICE"
if aws ecs describe-services \
     --cluster "$ECS_CLUSTER" --services "$ECS_SERVICE" \
     --region "$AWS_REGION" \
     --query 'services[?status==`ACTIVE`]' --output text | grep -q "$ECS_SERVICE"; then
  echo "already exists"
else
  aws ecs create-service \
    --cluster "$ECS_CLUSTER" \
    --service-name "$ECS_SERVICE" \
    --task-definition "$ECS_TASK_FAMILY" \
    --desired-count 1 \
    --launch-type FARGATE \
    --network-configuration "awsvpcConfiguration={subnets=[${VPC_SUBNETS}],securityGroups=[${VPC_SECURITY_GROUPS}],assignPublicIp=ENABLED}" \
    --region "$AWS_REGION" >/dev/null
  echo "created"
fi

# 6. GitHub OIDC provider
log "Ensuring GitHub OIDC provider"
OIDC_ARN="arn:aws:iam::${AWS_ACCOUNT_ID}:oidc-provider/token.actions.githubusercontent.com"
if aws iam list-open-id-connect-providers \
     --query "OpenIDConnectProviderList[?Arn=='${OIDC_ARN}'].Arn" \
     --output text | grep -q .; then
  echo "already exists"
else
  aws iam create-open-id-connect-provider \
    --url https://token.actions.githubusercontent.com \
    --client-id-list sts.amazonaws.com \
    --thumbprint-list 6938fd4d98bab03faadb97b34396831e3780aea1 >/dev/null
  echo "created"
fi

# 7. GitHub Actions deploy role (OIDC trust)
log "Ensuring deploy role: $OIDC_ROLE_NAME"
TRUST_FILE="$(mktemp)"
cat > "$TRUST_FILE" <<JSON
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "${OIDC_ARN}"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "token.actions.githubusercontent.com:aud": "sts.amazonaws.com"
        },
        "StringLike": {
          "token.actions.githubusercontent.com:sub": "repo:${GITHUB_ORG}/${GITHUB_REPO}:ref:refs/heads/${GITHUB_BRANCH}"
        }
      }
    }
  ]
}
JSON

if aws iam get-role --role-name "$OIDC_ROLE_NAME" >/dev/null 2>&1; then
  echo "already exists — updating trust policy"
  aws iam update-assume-role-policy \
    --role-name "$OIDC_ROLE_NAME" \
    --policy-document "file://${TRUST_FILE}"
else
  aws iam create-role \
    --role-name "$OIDC_ROLE_NAME" \
    --assume-role-policy-document "file://${TRUST_FILE}" >/dev/null
  echo "created"
fi
rm -f "$TRUST_FILE"

DEPLOY_POLICY_FILE="$(mktemp)"
cat > "$DEPLOY_POLICY_FILE" <<JSON
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ECRAuth",
      "Effect": "Allow",
      "Action": "ecr:GetAuthorizationToken",
      "Resource": "*"
    },
    {
      "Sid": "ECRPushPull",
      "Effect": "Allow",
      "Action": [
        "ecr:BatchCheckLayerAvailability",
        "ecr:GetDownloadUrlForLayer",
        "ecr:BatchGetImage",
        "ecr:InitiateLayerUpload",
        "ecr:UploadLayerPart",
        "ecr:CompleteLayerUpload",
        "ecr:PutImage"
      ],
      "Resource": "arn:aws:ecr:${AWS_REGION}:${AWS_ACCOUNT_ID}:repository/${ECR_REPO}"
    },
    {
      "Sid": "ECSRegisterAndDeploy",
      "Effect": "Allow",
      "Action": [
        "ecs:RegisterTaskDefinition",
        "ecs:DescribeTaskDefinition",
        "ecs:UpdateService",
        "ecs:DescribeServices"
      ],
      "Resource": "*"
    },
    {
      "Sid": "PassRoleToECS",
      "Effect": "Allow",
      "Action": "iam:PassRole",
      "Resource": [
        "arn:aws:iam::${AWS_ACCOUNT_ID}:role/${EXEC_ROLE_NAME}",
        "arn:aws:iam::${AWS_ACCOUNT_ID}:role/ecsTaskRole"
      ]
    }
  ]
}
JSON

aws iam put-role-policy \
  --role-name "$OIDC_ROLE_NAME" \
  --policy-name GitHubActionsECSDeploy \
  --policy-document "file://${DEPLOY_POLICY_FILE}"
rm -f "$DEPLOY_POLICY_FILE"

DEPLOY_ROLE_ARN="arn:aws:iam::${AWS_ACCOUNT_ID}:role/${OIDC_ROLE_NAME}"

Review checklist

  • Tests pass locally.
  • docker build succeeds.
  • Perubahan pada workflow / task def / deploy.sh diuji pada non-prod AWS.

Rules

  • Jangan push terus ke gh-pages tanpa review kecuali hotfix.
  • Jangan commit AWS credentials. Guna OIDC.
  • Jika ubah OIDC trust policy, koordinasi dengan pemilik akaun AWS.
  • Rollback = re-run workflow lama, bukan git revert + push.

  `gh-pages`.

  GitHub secrets.

Short version (GitHub Release body)

### ECS deployment pipeline

Push-to-deploy to Amazon ECS from `gh-pages`, authenticated via GitHub OIDC —
no long-lived AWS keys.

**Setup**
1. Edit the CONFIG block in `deploy.sh`.
2. Run `./deploy.sh`.
3. Paste the printed `env:` block and `role-to-assume` ARN into `.github/workflows/aws.yml`.
4. Push to `gh-pages`.

**Breaking changes:** none

Troubleshooting

SymptomLikely cause
Not authorized to perform sts:AssumeRoleWithWebIdentity Trust policy sub tidak sepadan dengan repo/branch. Jalankan semula deploy.sh selepas fix GITHUB_ORG / GITHUB_REPO / GITHUB_BRANCH.
denied: requested access to the resource is denied (ECR push) ARN dalam ECRPushPull tidak sepadan. Semak ECR_REPO.
ECS task mati serta-merta Semak CloudWatch Logs di /ecs/<task-family>.
Service tidak stabilize Subnet tiada route ke NAT/IGW. Semak VPC_SUBNETS dan VPC_SECURITY_GROUPS.
CannotPullContainerError Execution role tiada AmazonECSTaskExecutionRolePolicy, atau image URI salah.

Rollback

Re-run workflow dari commit sebelumnya dalam tab Actions, atau secara manual:

aws ecs update-service \
  --cluster "$ECS_CLUSTER" \
  --service "$ECS_SERVICE" \
  --task-definition "$ECS_TASK_FAMILY:PREVIOUS_REVISION" \
  --region "$AWS_REGION"

Senarai revisi:

aws ecs list-task-definitions \
  --family-prefix "$ECS_TASK_FAMILY" \
  --region "$AWS_REGION"
